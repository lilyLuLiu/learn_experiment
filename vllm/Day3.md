## 🟡 Part 3：KV Cache（推理加速核心🔥）
全称是 Key-Value Cache（键-值缓存）。它用来避免重复计算，大幅提升文本生成的速度。
#### KV Cache 的核心思想
在 Transformer 的注意力机制中，每个词都要和之前所有词的 Key 和 Value 做运算。

关键观察：当生成第 $t+1$ 个词时，前 $t$ 个词的 Key 和 Value 其实不会变（因为那些词已经固定了）。所以不需要每次都重新算，而是：

第一次计算时：把每个词的 Key 和 Value 缓存下来（存到 KV Cache 里）。

后续生成时：只计算新词的 Key 和 Value，然后从缓存里取出之前所有词的 Key/Value 一起做注意力
#### ❗ 没 KV Cache 会发生什么？
每生成一个 token：重新计算所有历史 token❌ 

#### 🚀 加速效果
|模式	|速度|
|-|-|
|无 cache	|慢|
|有 cache	|快 10~20倍|
#### 代价是什么？
显存占用：需要存储所有历史词的 Key 和 Value。对于长上下文（如 128K）和大模型（如 70B），KV Cache 可能占据数 GB 甚至数十 GB 显存。

因此出现了 GQA（分组查询注意力）、MQA（多查询注意力） 等变体来减少 KV Cache 的大小。
#### 🧠 一句话解释
>KV Cache = “记住之前算过的注意力结果”

## 🧪 Part 5：实战（判断模型能不能跑🔥）
#### 🎯 练习1：你电脑能跑吗？

1. 假设：
GPU = 8GB

2. 问：7B模型能跑吗❓

* 👉 FP16：14GB ❌ 不行

* 👉 INT4：4GB ✅ 可以
#### 🎯 练习2：
GPU = 16GB, 13B模型
* FP16 → ❌ 不行
* INT4 → ⚠️ 勉强可以
##### 为什么
13B × 0.5字节 = 6.5GB，权重部分占用的显存大约在 6.5GB 至 7.5GB 之间。
模型权重并非显存占用的全部。在实际运行时，还需要考虑以下额外开销：
* KV Cache：这是存储已生成内容的“记忆”，会随着对话长度线性增长，是长文本对话时的显存“隐形杀手”。
* 中间激活值：模型在计算时产生的临时数据，也会占用部分显存。
* 推理框架开销：加载模型框架本身也需要一点空间。

综合这些因素，一个13B模型的INT4量化版本在推理时，总显存占用大约在 10GB 至 13GB 之间。因此，16GB的显存是足够用的。

>⚠️ 需要特别留意的是，以上估算基于“推理”场景。 如果你计划进行模型微调（如使用LoRA等技术），显存需求会成倍增加。对于13B模型的微调，即使是INT4量化，16GB显存也会非常紧张。

#### 🎯 练习3：推理 vs 训练
训练通常需要推理 3~4 倍以上的显存，甚至更多。
用同一个模型（例如 13B 参数、INT4 量化）来对比：
* 推理：16GB 显存足够。
* 训练：16GB 远远不够，通常需要 40GB~80GB 甚至更多。

##### 核心差异：推理 vs 训练的内存需求
|组成部分	|推理（Inference）	|训练（Training）|
|-|-|-|
|模型权重	|需要	|需要（可能需额外副本）|
|梯度	|❌ 不需要	|✅ 需要（与权重同大小）|
|优化器状态	|❌ 不需要	|✅ 需要（Adam 需 2 倍权重大小）|
|中间激活值	|✅ 需要（较小）	|✅✅ 需要（很大，且需保留用于反向传播）|
|计算图	|❌ 不需要	|✅ 需要（记录所有操作）|
|临时缓冲区	|少量	|大量|
